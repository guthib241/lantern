# Decisions

- Oct 26: OpenAI Python SDK used as the HTTP client because Meta Model API is OpenAI-compatible (per dev.meta.ai quickstart).
- Oct 26: Research findings adopted (see docs/SPEC.md v2): WhatsApp scoped as a personal task/approval console because of WhatsApp's Jan 2026 AI-provider rule, Telegram as fallback; glasses via built-in WhatsApp voice messages, not the glasses SDK; Electron for the overlay; sqlite-vec for local embeddings; Muse Glimmer lane is just an OpenAI-compatible URL so it can be local or self-hosted on Modal.
- Oct 26: User laptop = RTX 4060 Laptop 8 GB VRAM, Ryzen 7, 15.6 GB RAM, 1 TB. Official Glimmer Q4_K_M (~19 GiB) does not fit. Plan: private lane runs Glimmer IQ2_M / IQ2_XXS GGUF (~9-11 GB) in llama.cpp with partial GPU offload, text-only (skip the 1.4 GB vision projector), `-c 8192`, used only for short private tasks (classify, summarise, redact, answer about a private file). Backup: self-hosted Glimmer on Modal. Local embeddings use a small embedding GGUF on CPU. During the demo, close other heavy apps (RAM is tight with Electron + Chromium + model).
- Oct 26 (M2): Paths outside every zone rule are treated as hidden, and the error for a hidden path is the same "outside the folders" message, so the model can't probe for hidden folders. A small set of names (`.ssh`, `.gnupg`, `.aws`, `.env*`, browser login stores, `.lantern`) is always hidden regardless of zones.json. Moving a file needs both source and destination in writable zones (moving changes the source folder too). Without a zones.json, configured roots are writable, so M0 behaviour is unchanged. Private files: the cloud model gets name/type/size/line-or-page count only; content search skips them.
- Oct 26 (M3): Scrubber is our own regex set (no detect-secrets/gitleaks dependency) so it stays small and auditable; card numbers need a Luhn pass and Aadhaar a Verhoeff pass to avoid redacting order numbers. Emails and phone numbers are *not* scrubbed by default because Lantern must address emails and WhatsApp replies; both can be turned on. Scrubbing happens in `GuardedClient` around the OpenAI-compatible client, on `instructions`/`input`/`messages` only; the tool list is never touched so the request prefix stays byte-stable for prompt caching. Audit log is a separate SQLite file (`~/.lantern/audit.db`); the SHA-256 is of the exact scrubbed payload that was sent.
- Oct 26 (M4): Private lane is a tool (`ask_private(path, question)`), not a hidden reroute of the whole conversation: the cloud agent plans, Glimmer reads the private file locally and returns at most a few sentences, which are scrubbed again before going back. If Glimmer is down the tool errors; there is no cloud fallback. Default mode is `fake` (extractive offline answers, badge "Muse Glimmer (fake)") until `LANTERN_GLIMMER_URL` is set. A non-loopback Glimmer URL (Modal) is audited as lane `selfhosted`, shown separately from `local`. Requests use the documented Glimmer sampling (temp 1.0, top_p 0.95, top_k 64) and `reasoning_strength: low` to keep the 8 GB laptop fast.
